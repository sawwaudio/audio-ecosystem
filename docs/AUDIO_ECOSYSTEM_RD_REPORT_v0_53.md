## 2. 重さの原因と対策
- 測定（ヘッドレス Chromium、再生を押してから20秒）：v0.52 は FLAC を **約32MB** 読み込んでいた。
  - セミの合唱 9.2MB、波 7.5MB、川 5.9MB など。既定の音源が「FLAC（原本と同じ音）」だったため。
  - ページ本体（gzip 後 約365KB）と写真（12枚 約390KB）は主因ではない。
  - CPU は再生中12〜13%で、問題ではない。
- 対策1：**軽量の音源（MP3 VBR 約175kbps）を既定にした**。
  - build/make_lite_audio.py で作成した。118録音・73MB（FLAC 712MB の約10%）。
  - ステレオはステレオのまま。96kHz の録音は 48kHz に下げた。
  - 置き場所は音源リポジトリの audio/lite/。
  - 聞こえる帯域（15kHz 以下）の RMS は FLAC と ±0.31dB 以内。gain は FLAC と同じ値を使う。
  - FLAC がない9録音は、従来の互換 MP3 を使う。楽器は互換 MP3 を使う。
  - **結果：20秒の通信量 32MB → 5.5MB**。
- 対策2：**一度鳴らした音を端末に保存する**（Service Worker、sw.js、ソースは build/src_sw.js）。
  - 音源・書体・CORS で読んだ写真は、端末に保存したものを先に使う。最大700件。
  - ページは通信を優先し、4秒で返らないか、つながらない時は保存した版を出す。
  - 電波がない状態で再読み込みしても開き、前に鳴らした音は鳴る（テストで確認）。
- 高音質（FLAC）は「設定と権利 → 音質と通信」で選べる。選択は端末に記憶する。

## 3. 画面の重複を減らした所
| 変更 | 理由 |
|---|---|
| 絞り込みから「再生中」「写真あり」を外した。「自分の音」は読み込んだ時だけ出す | 再生中は下のバーの「♪ 一覧」と同じ役目。写真ありは使われない |
| タイルの区分の文字（A/B/C）は、商用モードで鳴らない時だけ出す | ふだんは意味の分かりにくい記号が並んでいた |
| プランの比較表を「機能を比べる」に畳んだ | 料金のカードだけで足り、表が画面の真ん中を大きく取っていた |
| 設定を「音質と通信 → 商用モード → 設定の保存 → クレジット → 詳しい情報（確認・開発用）」の順にまとめた | 音源の形式・監査表・DB・診断は開発向け。1つに畳んだ |
| 英語だけのボタン名を日本語にした（和音を変える・自動作曲 オン・音の細かさ・この端末に保存・ファイルに書き出す など） | 日本語画面で英語が混ざっていた。英語表示では従来どおり英語 |
