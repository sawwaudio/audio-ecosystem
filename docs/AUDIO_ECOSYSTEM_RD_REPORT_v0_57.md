## 2. 作ったもの
| 部分 | 内容 |
|---|---|
| 課金の確認サーバー（server/worker.js、Cloudflare Workers） | Stripe の Webhook（署名を確かめる）で、有料会員を KV に記録する。署名付きの「PRO の証明」（ES256 の JWT、期限は次の更新日＋3日、最長40日）を発行・更新する。エンドポイントは /activate（支払い後の移動先）・/login（ログイン用メール）・/magic・/refresh |
| アプリ（src_studio.js） | 公開鍵で証明を確かめて PRO を開放する（電波がなくても期限まで PRO）。購入ボタン（支払いリンク＋client_reference_id）、購入済みの人のメールでのログイン、PRO の人の「支払い・領収書・解約の管理」（Stripe の顧客ポータル）とログアウト |
| 無料版の制限 | PRO の楽器（v0.55）と、PRO の欄（ミキサー・サンプラー・トラック）が開かない |
| 領収書 | Stripe の自動メールを使う（設定の手順は server/README.md の1） |

- **安全の考え方**
  - アプリに入るのは公開鍵だけ。秘密の鍵・Stripe の鍵（読み取り専用の制限付きキー）・メールの鍵は、サーバーの secret にだけ置く。
  - カード情報は Stripe の画面だけで扱う。
  - ログイン用メールは、会員でないアドレスには送らない。返事は同じにして、登録の有無を漏らさない。同じアドレスへは1分に1回まで。
  - ログイン用リンクは20分・1回だけ有効。
- **今の状態**：data/product_tiers.json の checkout.status は 'test' のまま。サーバーを置いて status を 'live' にするまでは、テスト公開（全部使える）のまま変わらない。
- **Stripe の API の版の違い**：購読の期限（current_period_end）が購読そのものにある旧い版と、明細にある新しい版（2025-03-31 以降）の両方に対応した。

## 3. オーナーがすること（server/README.md）
1. Stripe：「支払いの成功」メールをオンにし、公開のビジネス情報を入れる（領収書）。
2. Stripe：顧客ポータルを有効にする（解約・カードの変更）。
3. Stripe：制限付きキーを作り、Webhook を登録し、支払いリンクの「支払い後」に /activate を入れる。
4. Cloudflare：Workers に置き、secret を入れる。
5. Resend：ログイン用メールの送り元を用意する。
6. 公開鍵・サーバーの URL・顧客ポータルのリンクを Claude に渡す → Claude が status を 'live' にして公開する。
7. 特定商取引法に基づく表記と、定期購入の最終確認画面の表示を確かめる（専門家に確認）。
