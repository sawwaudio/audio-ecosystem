# AUDIO ECOSYSTEM — 自動改善ブリーフ（定期実行用）

この文書は、5時間ごとに起動する自動改善セッションへの常設指示。各セッションは会話の記憶を持たないため、毎回この文書を最初に読む。

## 最終目標
AUDIO ECOSYSTEM を、**ソフトウェアとして販売できる品質**まで継続的に改善する。
実在する生物・自然の実録音を、高音質・正確な出典・安定した再生で、自由に演奏・自律生成できるアンビエント制作環境。

## 1回の実行手順
1. この文書、`AUTOMATION_LOG.md`、最新のR&Dレポートを読む。
2. Artifact を `action:"read"` で読み、`index.html` と必要な `data/*.json`、`dev/*` を作業ディレクトリに取得する。
3. バックログから**1〜2件**、販売品質への寄与が最も大きいものを選ぶ（下の優先順）。大きな作業は分割し、1回で完了できる単位にする。
4. 実装する。既存機能（25レイヤー、32自然録音以上、8音色、15楽器、試聴、WAV録音、プリセット、PCM/原本/MP3切替、地域フィルター、監査表、DB）を壊さない。
5. Playwright（ローカルの http.server で配信）で回帰テストを行う：コンソールエラー0、自律演奏開始、PCM/MP3切替、地域フィルター、390px幅で横はみ出しなし、v0.23とのパリティ（25レイヤー・8音色）。テストが通らなければ公開しない。
6. 同じ Artifact URL に再公開する（`url` を指定。読み込み済みの最新版に変更を重ねる）。変更した `dev/` ファイルも一緒に公開する。
7. `AUTOMATION_LOG.md` に、日時・やったこと・テスト結果・未検証事項・次の候補を追記する。版を上げたら R&D レポートの新版をプロジェクトに書く。
8. 何も安全に改善できない場合（テスト失敗、取得不可など）は、公開せずにログだけ残す。

## 改善の優先順（上ほど優先。ロードマップのフェーズ順に進める）
0. **ロードマップの現在フェーズのバックログ**（日本語／英語切替、リールモードなど）。
1. **再生の安定性**：iPhone Safari での発音（WAV経路・24-bit・低サンプルレート）、メモリ上限、長時間再生、クリックノイズ、エラー時の復帰。
2. **新規音源の取り込み**：候補マスターで「採用可能」（CC0 / CC BY / PD）と確認済みのもののみ。取得済みファイルがプロジェクトかArtifactにある場合に限り、SHA-256・重複照合・ラッパー（PCM/互換MP3）・メタデータ（分布と録音地を分ける）を付けて追加。
3. **自律生成の高度化**：種ごとの発声確率、鳴き交わし、時間帯・季節、密度制御、空間配置、非反復性、ドローン／グラニュラー。
4. **販売に必要な要素**：クレジット・ライセンス表示（CC BY の帰属を画面と書き出しに必ず含める）、利用規約・出典ページ、オンボーディング、プリセット管理、書き出し、オフライン対応（PWA化の検討）、アクセシビリティ、パフォーマンス、デザインの一貫性。
5. **品質管理**：自動テストの拡充、ビルドの再現性、ドキュメント。

## 守ること（指示書の原則）
- 実装済みと計画を混同しない。検証していないものは「未検証」と書く。
- 原本優先。MP3→WAV 変換を高音質化と呼ばない。原本を復号したPCMは「原本と同等」と書き、「非圧縮マスター」と呼ばない。
- 分布と録音地を混同しない。未確認の分布を日本産と判定しない。該当音源がない地域で他地域の録音や合成音を代用しない。
- CC BY-NC・権利保留・再配布不可・合成音・種名に疑義のある録音は採用しない。
- 種名が不明な録音を推測で特定種にしない。複数種の環境録音を単独種として数えない。飼育下と野外を区別する。
- 既存の元録音データ・ライセンス情報・出典を失わない。ファイルを削除しない。
- 外部への投稿・送信・購入・アカウント操作はしない。ネットワーク制限を回避しない（許可されていない宛先は記録して終える）。
- ダウンロードは、候補マスターで「採用可能」と確認済みの音源に限る。Chrome が接続されていない場合は行わない。
