# AUDIO ECOSYSTEM — R&D REPORT v0.23
**開発記録：2026年10月30日**  
**改訂日：2026年10月31日**  
**用途：Claude開発引き継ぎ・技術仕様・品質管理**

## 0. 開発目標

AUDIO ECOSYSTEMは、自然界の実録音と音響合成技術を統合し、生物・気象・水・環境音を自由に演奏、加工、自律生成できる音楽制作アプリケーションである。

最終目標は、高い原音忠実度と自由な音楽表現を両立する、統合型のアンビエント生成環境を完成させること。

今後の開発では、特に以下を重視する。

1. 非圧縮音源による高品質な再生
2. 自然音と実楽器録音の拡充
3. iPhone Safariを含む再生安定性
4. 自律生成エンジンと演奏機能の高度化
5. 長時間運用に対応する音源・メモリ管理

**重要：本書の実装済み事項はv0.23時点の記録である。非圧縮化は新たに決定した開発方針であり、実装済みではない。**

## 2. 新方針：非圧縮オーディオへの移行

### 2.1 基本仕様

今後、音源ライブラリをMP3中心から非圧縮PCM中心へ段階的に移行する。

| 項目 | 目標仕様 |
|---|---|
| 標準形式 | WAV（Linear PCM） |
| 追加対応形式 | AIFF（Linear PCM） |
| 基準サンプルレート | 48kHz |
| 基準ビット深度 | 24-bit |
| DSP内部演算 | 32-bit float |
| 書き出し | 16/24-bit PCM WAV |
| チャンネル | Mono / Stereo、将来のマルチチャンネル対応を検討 |

WAVとAIFFは、同一PCMデータであれば音質上の優劣はない。

Webアプリケーションの互換性を優先し、WAVを標準形式として採用する。

AIFFは読み込みをサポートし、必要に応じてPCMデータを非圧縮のままWAVへ変換する。

### 2.2 音源品質の原則

**元録音の品質を維持することを最優先する。**

- 非圧縮マスターが存在する場合はそれを利用する。
- MP3をWAVに変換しても失われた音声情報は復元されない。
- 元録音が16-bit / 44.1kHzなら、無意味な24-bit / 48kHz化を音質改善として扱わない。
- 元の録音チャンネル数を維持する。
- ステレオ素材を不必要にモノラル化しない。
- 過剰なノイズ除去、EQ、ノーマライズを避ける。
- 再生時の変換処理と原本マスターを明確に区別する。

非圧縮形式の採用そのものは、既存MP3より優れた音質を保証しない。元録音の品質とマスターの来歴を重視する。

### 2.3 音源の優先順位

1. 原録音の非圧縮WAV/AIFF
2. 非圧縮PCMと同等の情報を保持するロスレスマスター
3. 高品質の非可逆圧縮音源
4. 既存MP3互換音源

非圧縮マスターがない場合は、既存音源を削除せず維持する。

## 3. 新オーディオエンジン設計

### 3.1 再生

Web Audio APIを中心に設計する。

- AudioBufferによる短尺素材の再生
- 長尺素材のストリーミング
- AudioWorkletによる高度なDSP処理
- 再生速度とピッチの制御
- シームレスループ
- レイヤーごとの独立制御
- ステレオ定位と空間配置
- クリックノイズ防止
- 出力ピーク管理
- 長時間再生の安定化

音源の長さ、用途、端末メモリに応じて再生方式を切り替える。

### 3.2 メモリ管理

現行システムには自然録音PCM128MiBの上限があり、楽器サンプルは別キャッシュとして管理されている。

今後は自然録音と楽器サンプルのメモリ使用量を統合管理する。

- LRUキャッシュ
- 必要時ロード
- 不使用音源の解放
- 同時発音数の制御
- 大容量音源のストリーミング
- 読み込み・デコード処理の監視

### 3.3 アプリ構成

非圧縮音源の容量増加に対応するため、音源データとHTMLアプリ本体を分離する。

推奨構成：

- アプリ本体：HTML / CSS / JavaScript
- 音源：独立WAVファイル
- 音源情報：JSONメタデータ
- 権利情報：ライセンス台帳
- プリセット：独立した設定データ

iPhoneでの利用方法、オフライン利用、配信コスト、ブラウザの保存容量を検証して構成を決定する。

## 4. 自然録音ライブラリ

### 4.1 優先収録対象

日本の自然環境を優先する。

**生物音**

鳥類、直翅目、セミ、カエル、その他の生物。

**環境音**

森林、雨、風、渓流、湧水、海岸、岩場、洞窟、湿地。

特に伊豆を含む日本国内の実録音を重視する。

### 4.2 メタデータ

各録音に以下を記録する。

- 生物名・学名
- 録音者
- 録音場所
- 録音日時
- 原典URL
- ライセンス
- 原本形式
- サンプルレート
- ビット深度
- チャンネル数
- 録音時間
- ファイルサイズ
- SHA-256
- 加工履歴

現行の `recording_licenses.json` を継承・拡張する。

ライセンスの取得・確認状況と、実際のアプリ収録状況を区別して管理する。

### 4.3 権利管理

現行の原本は `audio/`、楽器サンプルは `instruments/`、原典資料は `evidence/` に保存されている。

VCSLは固定コミット `c1ea7bcc3c7309650ab0da9d15c9cd1fbc4a4c7e` を使用している。

Philharmoniaの素材はサンプラー用途での再配布制約があるため、採用していない。

CC BY-SAの条件が適用される素材については、改変・配布・帰属表示・継承条件を確認する。

## 7. 既知の課題

### 音源品質

現行の互換再生音源はMP3であり、非可逆圧縮による情報損失がある。

### 容量

現行HTMLは原本保持と互換MP3の内蔵により約43MB。

非圧縮音源を追加すると容量とメモリ消費が増えるため、分離管理と必要時ロードが必須になる。

### 再生互換性

現行の試聴経路はChromiumで検証されたが、iPhone Safari実機での再生成功は確認されていない。

### 原本品質

前版から継承された録音の一部には抜粋版がある。可能な限り全長マスターを確認・取得する。

## 11. Claudeへの引き継ぎ原則

1. `AUDIO_ECOSYSTEM_v0_23.html` を開発正本とする。ただし、これより新しい正本が存在する場合は差分を確認する。
2. 本R&Dレポートは仕様と開発履歴であり、実行コードの代替ではない。
3. 既存25レイヤー、32自然録音、8楽器音色、15実楽器サンプルの機能を維持する。
4. 実装済み機能と将来の開発計画を混同しない。
5. 音源は原本優先で扱い、MP3からのWAV変換を高音質化とみなさない。
6. 実際に再生・操作できる統合アプリを毎回更新する。
7. 検証できなかった環境や機能は未検証と明記する。
8. 元の録音データ、ライセンス情報、出典を失わない。
9. 実装後は変更差分とテスト結果をR&Dレポートに反映する。

**最終開発原則：既存の動作資産を保持しながら、実録音の品質・再生安定性・音楽表現の自由度を段階的に高める。**
